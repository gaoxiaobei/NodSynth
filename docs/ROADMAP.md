# 开发路线

更新日期：2026-10-05。当前已经具备多轨 MIDI、歌曲命令、混音/分轨、外部合成器、VST3 和基础 DAW 界面；下一轮重点是让 Agent 从空白工程顺畅创作。

详细范围与验收条件见 [编曲工作台迭代设计](ITERATION-COMPOSING.md)。基础架构仍参考 [编曲套件设计](COMPOSITION-SUITE.md)。

## 已交付底座：A/B/C

| 顺序 | 交付 | 关键验收 | 状态 |
|---|---|---|---|
| A 接口可信 | 全实体 diff、分层/过滤/分页 query、来源与轨序澄清、静音时长、渲染耗时拆分 | 混音修改可审阅，查询输出有界，不以单采样静音误报 | 已实现 |
| B 原生创作 | 空白歌曲、建轨/命名/片段、批量编排、预设库、Noise 与鼓音色 | Agent 从空白做 16 小节，无中间 SMF，无手写音色图 | 已实现 |
| C 快速试听 | 成品裁片、轨道缓存与重混音、分析校准、A/B 试听交接 | 暖缓存试听目标 ≤2 秒且较冷渲染快至少 5 倍，状态正确 | 已实现（本机 Release：裁片约 5 ms，暖重混音约 50 ms，冷全曲约 5.76 s） |

性能目标在固定机器 Release 环境复测；先分解耗时，再决定优化，不跳过有状态预跑来伪造速度。鼓音色和最终作品需要人工试听，峰值/LUFS 不代替音乐质量评价。

## 当前迭代：D0–D2

选择性采纳 [Agent 复测反馈](AGENT-COMPOSING-FEEDBACK.md)，具体取舍和验收以 [迭代设计](ITERATION-COMPOSING.md) 的“第二轮”章节为准。原始反馈是体验证据，不是未经筛选的全部需求。

| 顺序 | 范围 | 验收重点 | 状态 |
|---|---|---|---|
| D0 正确性 | 同一资源路径基准、复制收集预设、可搬移工程、批量 diff 摘要；拒绝不支持的自动化 | 任意 CWD 操作一致，搬移后渲染，602 音符摘要准确，不能静默忽略 lane | 已实现，自动验收通过 |
| D1 可控声音与试听 | NodSynth 采样精确参数自动化、能力/单位约定、PCM16 试听导出、独立试听记录 | cutoff 确实改变音频且缓存正确；播放器启动不等于 heard | 已实现，自动验收通过；人工试听待确认 |
| D2 乐句与曲风 | pattern 展开、移调/力度/按小节复制、有限和弦辅助、宏参数与精简曲风包 | 无逐 tick 列表、无手写 Patch 完成 trance；house 小样验证泛化 | 已实现，自动验收通过；曲风听感待确认 |

保留 float32 母带默认值，增加兼容试听产物；工程资源默认复制，不用 junction；不猜测相对路径基准。D0 先补可靠性，D1 自动化打通后再扩大曲风包。按轨并行、复杂 DSP、模板/registry 管理和响度归一化后置，不因单曲 LUFS 较低就自动抬响度。

本轮不扩展新后端。保持既有暖缓存与精简 query 的性能，保留用户创作文件，另建 138 BPM、16 小节、至少 7 轨 trance 验收及 17 小节边界/house 对照；听感继续由人确认。没有“当天完成”的工期承诺。
