## M1：从编译图到第一段声音

目标：无需 JUCE、MIDI 设备或界面，用固定音符序列驱动图并输出 WAV。先采用单声部、正弦振荡器和有界事件容量，复用现有 PerVoice / Global 划分。

### 1. 定义运行契约

- [ ] 增加 `include/nodsynth/runtime/`、`src/runtime/` 与 `nod_runtime` 目标，定义 prepare 配置、采样率、最大块长、处理上下文、状态所有权和失败结果。
- [ ] 定义 Note/Gate 的采样偏移、同一采样点事件顺序、Note Off 配对、空输入默认值和缺失必要输入的处理规则；区分图合法与运行期可执行。
- [ ] 首版 Control 使用逐采样缓冲，明确参数基础值、调制深度、范围限制及默认值映射；常量/ramp 优化后置。
- [ ] 将运行计划拓扑与可变 DSP 状态分开，明确非实时构建/销毁和实时处理边界。缓冲区按类型、作用域和 slot 寻址。

验收：无需设备即可构造处理上下文；非法采样率、块长、未知 DSP 实现和超预算准备被明确拒绝；prepare 后不查字符串注册表、不分配内存。

### 2. 注册最小内置节点

- [ ] 增加 `include/nodsynth/nodes/`、`src/nodes/` 与 `nod_nodes`，通过内部注册接口关联 schema 与 DSP 工厂/处理函数，不直接设计稳定外部 ABI。
- [ ] 实现 MIDI Input 的内部音符事件适配、Note to Frequency、Sine Oscillator、ADSR、Gain、Voice Mix 和 Audio Output。
- [ ] 将 graphcheck 中可共用的内置 schema 移至节点模块，保留故意构造非法图的能力；现有 `nod.*` type ID 延续使用，变更需说明迁移策略。
- [ ] 确定最终输出端口、无输出图及多个输出节点的运行策略；加入非有限值静音和有界输出保护。

验收：A4 转换为 440 Hz；振荡器在 44.1/48/96 kHz 下频率正确且无 NaN/Inf；ADSR 时序落在明确采样容差内；Gain 与单声部到立体声汇聚符合定义。

### 3. 构建并执行预分配计划

- [ ] 从 `CompiledGraph` 绑定处理操作、物理缓冲区与默认参数；按既有调度顺序处理逐声部图，再处理全局图。
- [ ] 校验运行声部数与编译预算一致，计算真实字节占用，在 prepare 阶段拒绝超限计划。
- [ ] 覆盖缓冲区复用后的实际输出、同块 Note On/Off、跨块包络状态及最后不足一块的渲染。
- [ ] 在 M2 实现 Feedback Delay 前，准备阶段明确拒绝尚无 DSP 实现的延迟节点，不能仅凭可编译就执行。

验收：固定输入在相同配置下可重复渲染；64/128/512 samples 块长均正确；分配检测验证 prepare 后处理不分配内存，所有输出为有限值。

### 4. 交付离线渲染工具

- [ ] 增加 `apps/render/` 和拟定的 `nod_render` 目标，内置最小图与固定音符序列，提供输出路径、采样率与块长选项。
- [ ] WAV 写入在处理回调之外完成；无效参数或写入失败返回非零退出码。
- [ ] 增加 `tests/runtime/`、`tests/nodes/` 及集成测试；检查帧数、声道数、非零信号、Note Off 后释放到静音和频率误差，不只检查文件存在。
- [ ] 在 README 补充届时实际可用的命令及示例输出，保存验收记录。

M1 完成门槛：现有图测试继续通过；一条可复制命令输出能播放的立体声 WAV；数值测试与人工试听均完成。试听补充自动测试，不替代它。

## M2：完整合成与实时安全

1. 扩展到 16 声部：释放态优先、再选最旧活跃声部的确定性抢声；覆盖重复音符、不同 MIDI channel、sustain、all-notes-off 和抢声淡化。
2. 增加 Triangle/Saw/Square、低通滤波和 Add/Multiply/Scale-Bias/Mix；定义高频抗混叠方案、参数平滑和调制范围。
3. 实现 Feedback Delay 的历史读/本块写及至少一块延迟，明确块长变化时的重准备规则，验证自反馈与跨节点反馈不读到被复用覆盖的数据。
4. 引入有界参数通道与溢出策略，保证参数最终值可到达；MIDI 溢出需有避免挂音的恢复策略。
5. 后台准备新计划，块边界切换，重触发仍按住的音符，使用 10–20 ms 交叉淡化；旧计划在非音频线程回收。计入双计划峰值内存与 CPU，编译失败继续运行旧图。

退出条件：固定事件序列下抢声可重复；持续调参和切图无分配、死锁或 NaN/Inf；满队列、编译失败、资源超限与计划回收均有行为测试。离线测试不替代真实设备验收。

## M3：持久化和兼容

1. 定义 JSON 文件版本、节点版本、稳定 ID、参数、连接、私有数据和画布视口；设备 ID 保留在应用偏好中。
2. 补齐文档恢复和可撤销位置编辑；加载先恢复中立文档，再校验/编译，不在解析时创建 DSP。
3. 未知节点保留占位、参数、私有字段和连接；不可执行的工程仍可打开和再次保存。版本迁移先覆盖内置节点，不以第三方加载器为前提。
4. 同目录临时文件加原子替换，覆盖写入失败、损坏输入、不支持版本和未知字段往返。

退出条件：重载后节点与布局保持，固定输入渲染在约定容差内一致；失败保存不覆盖旧文件。

## M4：独立应用与设备演奏

1. 落实 JUCE 版本和许可证，增加与核心解耦的应用目标；保持无设备核心测试可单独构建。
2. 接入音频/MIDI 设备、采样率和块长设置，支持默认音色及屏幕键盘。
3. 音频断开保留工程；设备重启在非音频线程重新 prepare，失败保持静音并显示错误。

退出条件：Linux 真实设备上完成 16 声部演奏、Note Off、设备切换和恢复；记录驱动、硬件、采样率、块长及运行结果。

## M5：节点界面与发布验收

1. 实现节点搜索、创建、选择、移动、连接/断开、删除、缩放和平移，以及参数检查器和撤销/重做。
2. 补齐接线预检和可定位诊断；异步编译使用文档修订号，丢弃过期结果，保证最新编辑不被旧编译结果覆盖。
3. 接入保存/打开、默认音色和 2–3 个示例；显示编译状态、活跃声部数和非实时 CPU 遥测。
4. 完整验收：搭建振荡器 → 滤波 → Gain → Voice Mix → Output，ADSR 调制 Gain，演奏时改参数及结构，注入非法连线，再保存、退出、重开。

性能门槛：记录硬件及 Release 配置；48 kHz、128 samples、16 声部标准音色持续演奏 10 分钟，无 xrun、崩溃、挂音或明显切换爆音。记录回调耗时分位数，常态回调目标低于块时限的 50%，单独检查切换峰值。Windows/macOS 核心 CI 保持通过。

VST3/AU、正式 C ABI/SDK、动态扩展加载、Wasm、节点商店、复杂效果器和多平台打包在 MVP 后单独立项。不要提前冻结未经 DSP 验证的接口。

## Windows MVP 验收记录（2026-10-04）

机器：Intel Core 5 220H，约 32 GB 内存。编译器：LLVM-MinGW Clang 22.1.8。输出设备：Realtek 扬声器，WASAPI 共享模式。Debug 套件 `ctest --preset dev` 为 81/81 通过，包含三个 graphcheck 场景、工程往返、只读覆盖失败、过期异步编译被丢弃，以及 `runtime.no-allocation`（prepare 之后的 `process` 分配次数为 0）。

Release 配置 `nod_render --soak --sample-rate 48000 --block-size 128 --seconds 600` 处理了 225000 个回调，相当于 10 分钟音频。结果：`xruns=0`，释放后声部数为 0，输出保持有限值，中途切换到滤波音色成功。块时长 2.667 ms。p50 0.0558 ms（块时限的 2.1%），p99 0.0976 ms（3.7%），切换窗口峰值 0.0984 ms。单次最大回调 2.585 ms，仍低于一块的时限，因此没有记为 xrun。

应用 `nodsynth_app` 在本机打开默认正弦音色，状态栏显示音频正在运行。点击屏幕键盘后活跃声部从 0 变为 1；点选 Gain 后检查器出现增益滑块。`--self-test` 返回 0，覆盖编译、临时工程读写和默认输出设备。设备 ID 保存在用户的 NodSynth 偏好文件中，不写入工程。

同一台机器上的 Release 应用以 `--live-soak` 通过 WASAPI 实际演奏了 10 分钟：48 kHz，设备最终缓冲 1056 帧（共享模式没有接受 128 帧的请求），16 个音按住，输出增益降到 0.15 以免扬声器过载。进程约 611 秒后返回 0。结果是 `xruns=0`、释放后声部数为 0、p50 负载 1.0%、p99 负载 2.3%。128 采样的回调耗时以上面的离线测量为准。
