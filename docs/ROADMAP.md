# 开发路线

更新日期：2026-10-05。Windows 合成器 MVP 已完成；下一阶段转向命令行音乐制作与 AI 编曲套件。

详细设计、接口边界、MIDI 语义、联合渲染策略和验收条件见 [后 MVP 设计](COMPOSITION-SUITE.md)。原 MVP 计划与验收数据保留为[历史快照](history/MVP-2026-10-04.md)，其中旧待办不再用于跟踪新阶段。

## 新里程碑

| 阶段 | 交付 | 依赖 | 状态 |
|---|---|---|---|
| P1 | MIDI + 保存的音色 → 长时 WAV、尾音和报告 | 现有核心 | 已完成 |
| P2 | Song 工程、多轨多实例、统一时间轴、混音与分轨 | P1 | 待开发 |
| P3 | NodSynth 与一个真实外部合成器联合离线渲染 | P2 | 待开发 |
| P4a | NodSynth VST3，可在现成 DAW 使用 | P1，插件工具链验证 | 待开发，可按需求提前 |
| P4b | 套件 VST3 宿主、状态、自动化、延迟补偿 | P2，插件工具链验证 | 待开发 |
| P5 | AI 查询/事务编辑/试听闭环，支持撤销和修订冲突 | P2；联合渲染复用 P3/P4 | 待开发 |
| P6 | 基于同一核心的 DAW 界面与更多乐器/效果器 | P2、P5 的稳定接口 | 待开发 |

下一版本的完成标准：导入一份多轨 MIDI，明确分配不同合成器，用一条命令输出同步混音、分轨与渲染报告。多份 WAV 简单相加或固定音符演示不算通过。

## 当前开始顺序

P1 已完成：`nod_render --midi` 可把 SMF type 0/1 和已保存音色渲染为流式 WAV，并给出尾音与报告。下一步进入 P2 歌曲模型：

1. Song v1、MIDI 导入，以及按源 track/channel 的显式乐器映射。
2. 多个 NodSynth 实例、统一时间轴、增益/声像、混音与分轨。
3. 从零完整渲染和结构化报告；完成 P2 验收后再接外部合成器。

首个外部合成器暂以 FluidSynth 为候选，实施前确认实际目标及可用音色资产。若目标仅提供 VST3，则提前 P4b，联合渲染验收标准保持不变。当前没有工期承诺，按实际交付更新状态。
