下一版本的完成标准：导入一份多轨 MIDI，明确分配不同合成器，用一条命令输出同步混音、分轨与渲染报告。多份 WAV 简单相加或固定音符演示不算通过。

## 当前开始顺序

P1 至 P3 已完成。`nod render` 可以在同一首歌曲里同时渲染多个 NodSynth 实例和 FluidSynth（`--fluidsynth` 指向可执行文件，音源是 SoundFont）。外部分轨从样本 0 对齐，不裁掉开头；进程失败或超时会使整次渲染失败。FluidSynth 输出不承诺跨机器逐位一致。P5 的命令闭环已经可用：`nod song query`、带 diff 的 `apply`、`undo` / `redo`、从零预跑再裁切的 `--start-tick` / `--end-tick`，以及 `nod analyze` 的峰值、综合响度和静音。同一 request id 不会重复改歌。`nod song propose` 把查询和指令交给外部适配器，只写出命令批次，不在引擎里绑定模型供应商。P6 的 Windows 程序 `nod_daw` 能打开歌曲、显示钢琴卷帘和混音条、拖动改音、滚轮或推子改增益、拖动声像、播放渲染结果，并在面板里查看查询或应用命令。录音、音频片段、时间伸缩和侧链按设计留到这一版之后。P4a 的 `nodsynth_vst3.vst3` 已在 REAPER 7.82 里验收：音轨 MIDI 进入乐器，Gain 设为 0.25 后保存再打开仍是 0.25，离线导出的 16-bit WAV 峰值约 0.039。LMMS 1.2.2 只有 VST2，不能加载这个插件。P4b 宿主已经能加载 Serum 2 和 mda Delay，保存并恢复状态，并按采样推进时间线；插件进程崩溃会以非零退出码报告。mda Delay 的干声脉冲在采样 0，延迟副本在采样 8191，补偿后与该位置对齐。`nod render --vst3-worker` 用独立进程渲染 VST3 轨，插件加载失败或进程失败时不留下混音。插件自身报告的延迟会从分轨开头去掉。歌曲命令 `set-parameter-automation` 可以按采样推动 VST3 参数，NodSynth 的 Gain 已验证。报告延迟的插件会把输出整体后移，歌曲渲染再去掉这段前缀，脉冲仍落在音符起点；本机的 Serum 2 和 mda Delay 报告的延迟都是 0，这条路径用一个报告 128 采样延迟的探针插件验收。P5 的 8 小节场景由外部适配器读取工程：保留旋律、改写后 4 小节低音、补上和声，然后导出 MIDI、混音和分轨；撤销能回到原工程，同一 request id 不会改第二次。适配器仍是外部程序，引擎里没有绑定具体模型服务。

首个外部合成器暂以 FluidSynth 为候选，实施前确认实际目标及可用音色资产。若目标仅提供 VST3，则提前 P4b，联合渲染验收标准保持不变。当前没有工期承诺，按实际交付更新状态。
