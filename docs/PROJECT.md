# 项目目标与架构

更新日期：2026-10-05。本文区分产品目标与已实现能力；任务顺序以 [ROADMAP.md](ROADMAP.md) 为准，后 MVP 详细设计见 [AI 编曲套件设计](COMPOSITION-SUITE.md)。

## 产品目的

NodSynth 让用户以可视化节点连线的方式设计合成器音色。节点图就是声音结构：音符驱动振荡器，包络和控制信号调制音量与滤波，逐声部声音通过 Voice Mix 汇聚到立体声输出。

首个完整版本的用户闭环是：打开默认音色 → 用 MIDI 或屏幕键盘演奏 → 修改节点和参数 → 保存工程 → 再次打开后恢复声音与布局。

Windows 上的这个 MVP 闭环已完成。后续有两个并行产品目标：NodSynth 继续发展为独立、可嵌入和可供 DAW 加载的合成器；编曲套件提供无界面 DAW 核心，由 CLI、AI 与未来图形界面共用。歌曲时间轴、轨道、乐器映射与混音属于套件层，不进入合成器音色图模型。

下一产品闭环是：多轨 MIDI → 显式乐器/音色映射 → NodSynth 与外部合成器统一渲染 → 混音、分轨及报告 → AI 修改指定音乐片段后再渲染。

可演奏的闭环首先在这台 Windows 机器上验收。核心库继续面向 Windows、Linux 和 macOS 构建，应用外壳目前只在 Windows 上编译。后续再扩展其他平台的独立应用、VST3/AU 插件和第三方节点。

## MVP 边界

- 最多 16 声部的减法合成，具有确定的抢声规则和带采样偏移的音符事件。
- 内置 MIDI Input、Note to Frequency、Oscillator、ADSR、低通 Filter、Gain、基础控制运算、Voice Mix 和 Audio Output；完整 MVP 包含显式 Feedback Delay。
- 节点画布、参数检查器、设备选择、默认音色与少量示例音色。
- 演奏中调参和修改结构；非法新图提供可定位诊断，并保留上一份有效声音。
- 工程保存与恢复涵盖节点、参数、连接及画布状态。

上述是已完成 MVP 的范围。后续正式纳入歌曲模型、DAW 核心和标准乐器/效果器插件互通；自定义节点 SDK、扩展商店和多平台安装发行继续后置。标准插件宿主与 NodSynth 插件外壳分别交付，不等同于合成器内部节点扩展 ABI。

## 架构方向

```text
节点界面 → GraphDocument / GraphSnapshot → GraphCompiler → CompiledGraph
                                                        ↓
                                            运行计划构建与 prepare
                                                        ↓
离线渲染 / 实时音频外壳 ← DSP Runtime ← 预分配的执行计划与节点状态
```

`CompiledGraph` 仍是调度与逻辑缓冲区描述。`nod_runtime` 在此之上分配状态和物理内存，并生成可执行计划。

| 模块 | 责任 | 当前情况 |
|---|---|---|
| `nod_model` | schema、图文档、快照、编辑历史、视口 | 已实现 |
| `nod_compiler` | 校验、调度、逻辑缓冲区规划、连线预检 | 已实现 |
| `nod_graphcheck` | 固定图场景的命令行验证 | 已实现，schema 来自内置节点 |
| `nod_nodes` | 内置节点 schema、DSP 与示例音色 | 已实现 |
| `nod_runtime` | 运行计划、声部、参数平滑、计划切换 | 已实现 |
| `nod_persist` | JSON 工程、未知字段保留、原子保存 | 已实现 |
| `nod_render` | 离线 WAV 与 Release 性能测量 | 已实现 |
| `nodsynth_app` | Windows 音频/MIDI、画布、屏幕键盘 | 已实现；仅 `WIN32` |

C++20 核心不依赖 JUCE。这台机器没有 MSVC，Windows 外壳使用 WASAPI 与 winmm，因此没有引入 JUCE。仓库目前未提供项目许可证。

## 必须保持的约束

1. 节点类型、实例、端口、参数使用稳定 ID，显示名称不参与兼容判断。当前 ID 是强类型字符串封装，不假定已有 UUID 生成机制。
2. 四类端口不隐式转换；音频声道数必须相容。PerVoice 到 Global 通过显式边界端口汇聚，内置实现以 Voice Mix 提供这一语义。
3. 普通依赖不能成环。标记为延迟断点只解决编译调度，运行时还必须实现先读历史、后写本块的处理及独立状态。
4. 编译结果与诊断顺序保持确定性，不随节点插入顺序变化。
5. 编辑文档与音频状态分离。结构编译、内存分配、文件操作和旧计划销毁均在非音频线程完成；音频回调不等待锁、不分配内存、不格式化日志。
6. 参数变化走独立事件路径并平滑处理，不因每次旋钮变化而重建图。队列容量和溢出行为必须明确。
7. 新图准备失败时保留旧计划；无有效计划时静音。结构切换采用有界交叉淡化，并在非音频线程回收旧状态。
8. 工程保存失败不能破坏上次成功的文件；未知节点和私有数据需保留，以便重新保存及后续恢复。

## 实现事实与缺口

2026-10-04 在本机验证的能力见 [MVP 历史记录](history/MVP-2026-10-04.md)。图编辑、编译、运行时、工程文件和 Windows 应用都有对应代码与测试；本次设计未重跑历史验收。

- `nod_render` 保留正弦演示和 soak。`--midi` 读取 SMF type 0/1，可加载已保存音色，流式写出 WAV、尾音和 JSON 报告。仍然缺少歌曲模型、多实例混音与外部合成器适配。

- `GraphEditor::connect` 仍只拒绝重复连接和已被占用的输入。类型、声道和作用域错误由编译预检与异步编译诊断给出，非法结构不会替换正在发声的计划。
- Gate/Note 在编译结果里仍占 slot 0；运行时自己分配采样精确的 note、gate、velocity 缓冲。
- 设备 ID 写在 `%APPDATA%\NodSynth\preferences.json`，不进入工程文件。
- Linux 与 macOS 的远程 CI，以及 Linux 上的真实音频设备验收，这次没有运行。
